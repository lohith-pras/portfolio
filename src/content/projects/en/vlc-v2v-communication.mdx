# VLC V2V Communication

[View on GitHub →](https://github.com/lnlohith/vlc-v2v-communication)

A hardware prototype for Vehicle-to-Vehicle (V2V) communication using Visible Light Communication (VLC). LED headlights transmit digital data encoded via Manchester coding; photodiode receivers on trailing vehicles decode the signal in real time. The project targeted urban intersection safety scenarios — low-latency brake warnings without relying on RF spectrum.

## Phase 1
Hardware setup and LED calibration. Designed and calibrated the analog frontend: high-brightness LED array (transmitter), transimpedance amplifier (TIA) stage, and photodiode (receiver). Characterised the frequency response up to ~5 kHz at 1-meter working distance.

## Phase 2
Software protocol design. Implemented Manchester encoding in the MCU firmware to handle clock recovery and eliminate DC bias in the optical signal. The transmit loop below drove the LED pin directly on an Arduino-class board.

```cpp title="manchester_encoding.cpp"
#include <Arduino.h>

// Manchester state and timing definitions
const int TX_PIN = 12;
const unsigned long HALF_BIT_US = 500; // 1000 bps

void transmit_manchester_bit(bool bit) {
    if (bit) {
        // Logic 1: Transition Low → High
        digitalWrite(TX_PIN, LOW);
        delayMicroseconds(HALF_BIT_US);
        digitalWrite(TX_PIN, HIGH);
        delayMicroseconds(HALF_BIT_US);
    } else {
        // Logic 0: Transition High → Low
        digitalWrite(TX_PIN, HIGH);
        delayMicroseconds(HALF_BIT_US);
        digitalWrite(TX_PIN, LOW);
        delayMicroseconds(HALF_BIT_US);
    }
}

void transmit_packet(const uint8_t* data, size_t len) {
    for (size_t i = 0; i < len; i++) {
        for (int bit = 7; bit >= 0; bit--) {
            bool current_bit = (data[i] >> bit) & 0x01;
            transmit_manchester_bit(current_bit);
        }
    }
}
```

## Phase 3
Field testing in an indoor parking structure simulating a 10-meter V2V line-of-sight path. Measured BER vs. distance and identified ambient sunlight saturation as the primary failure mode above ~30 klux.

## What I'd Do Differently

- **Narrower-FOV photodiode with an optical bandpass filter**: The wide-angle photodiode I used saturated in direct sunlight — a showstopper for outdoor V2V scenarios. A receiver with a narrower field-of-view cone combined with a hardware optical bandpass filter (centred on the LED's emission peak) would have blocked ambient saturation at the analog level, before the TIA even sees it.
- **Hardware-driven Manchester encoding via SPI or a programmable state machine**: Soft-coding the Manchester timing in the main CPU loop worked at 1000 bps but introduced timing jitter that caused decoding errors at higher baud rates. Offloading the encoding to dedicated hardware — an SPI peripheral with a fixed clock, or a custom programmable state machine on a microcontroller with PIO support — would have given deterministic timing independent of interrupt latency.
- **Adaptive dynamic thresholding for bit slicing**: I used a fixed voltage threshold for the bit-slicer comparator. Distance fluctuations and changes in atmospheric scatter shifted the received signal amplitude enough to render the fixed threshold unreliable. An adaptive algorithm that tracks a short-window running average of the received envelope and updates the threshold dynamically would have made the link far more robust across operating conditions.
