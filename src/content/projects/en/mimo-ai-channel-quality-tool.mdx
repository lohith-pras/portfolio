# MIMO AI Channel Quality Tool

[View on GitHub →](https://github.com/lnlohith/mimo-ai-channel-quality)

This project focuses on predicting channel quality in 4×4 MIMO wireless systems using AI-based regression models. The goal was to replace classical heuristics with a data-driven pipeline capable of sub-millisecond CQI/SNR prediction at the edge — running on constrained hardware alongside the radio stack.

## Phase 1
Data collection and preprocessing of channel metrics from real-world MIMO measurements. Raw CSI matrices were captured from a 4×4 MIMO testbed, cleaned of NaN columns (caused by antenna dropout events), and normalized per-subcarrier before feeding into the training pipeline.

## Phase 2
Model training and evaluation. Tested gradient boosted regressors, lightweight MLPs, and a quantized PyTorch CNN. The MMSE channel estimator below was used as the classical baseline comparison — demonstrating the performance gap our AI model had to close.

```python title="channel_estimator.py"
import numpy as np

def estimate_cqi_snr(csi_matrix, noise_variance):
    """
    Estimates CQI and SNR from Channel State Information (CSI) matrix.
    Uses MMSE (Minimum Mean Square Error) channel estimation.
    """
    # H represents the channel matrix
    H = np.array(csi_matrix)
    # Compute Hermitian transpose
    H_hermitian = H.conj().T
    # MMSE receiver filter weight calculation
    identity = np.eye(H.shape[0])
    weight = H_hermitian @ np.linalg.inv(H @ H_hermitian + noise_variance * identity)

    # Estimate signal and interference plus noise power
    signal_power = np.abs(np.trace(weight @ H)) ** 2
    noise_power = noise_variance * np.trace(weight @ weight.conj().T)
    snr = 10 * np.log10(signal_power / noise_power)

    return snr
```

## Phase 3
Deployment and live testing on an Edge TPU dev board. The inference pipeline was exported via ONNX, validated against the MMSE baseline on a held-out dataset, and profiled for latency on device.

## What I'd Do Differently

- **Validate at 2×2 first**: I went straight to the 4×4 MIMO configuration. The multi-path correlation matrix errors I hit during the first training runs would have been caught and debugged in hours, not days, if I had validated the channel model pipeline at 2×2 first and scaled up only after confirming numerical stability.
- **Quantization-Aware Training in PyTorch**: I applied post-training dynamic quantization to shrink the model for Edge TPU deployment. This caused a ~1.8 dB SNR prediction accuracy degradation that I could only partially recover with calibration. Starting with quantization-aware training (QAT) baked directly into the PyTorch training loop from the beginning would have preserved accuracy while still hitting the target model size.
- **Dynamic batching for Edge inference**: The REST API wrapper I wrote around the inference engine added latency overhead that conflicted with the sub-1ms wireless latency target. A custom inference loop with dynamic batching, designed around the Edge TPU's DMA transfer characteristics from day one, would have kept the system within spec without the late-stage architectural rework.
