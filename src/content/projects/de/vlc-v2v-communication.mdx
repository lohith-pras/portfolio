# VLC-V2V-Kommunikation

[Auf GitHub ansehen →](https://github.com/lnlohith/vlc-v2v-communication)

Ein Hardware-Prototyp für die Fahrzeug-zu-Fahrzeug-Kommunikation (V2V) mittels Sichtlicht-Kommunikation (VLC). LED-Scheinwerfer übertragen digital codierte Daten per Manchester-Kodierung; Fotodioden-Empfänger an nachfolgenden Fahrzeugen dekodieren das Signal in Echtzeit. Das Projekt zielte auf Sicherheitsszenarien an städtischen Kreuzungen ab — Bremswarnsignale mit geringer Latenz, ohne HF-Spektrum zu nutzen.

## Phase 1
Hardware-Aufbau und LED-Kalibrierung für die optische Übertragungsstrecke. Entwicklung und Kalibrierung des analogen Frontends: Hochleistungs-LED-Array (Sender), Transimpedanzverstärker (TIA) und Fotodiode (Empfänger). Charakterisierung der Frequenzantwort bis ca. 5 kHz bei 1 Meter Arbeitsabstand.

## Phase 2
Entwurf des Software-Kommunikationsprotokolls und der Kodierungsschicht. Implementierung der Manchester-Kodierung in der MCU-Firmware zur Taktwiederherstellung und Unterdrückung von Gleichanteilen im optischen Signal. Die folgende Sendefunktion steuerte den LED-Pin direkt auf einem Arduino-ähnlichen Board.

```cpp title="manchester_kodierung.cpp"
#include <Arduino.h>

// Manchester-Zustand und Zeitdefinitionen
const int SENDE_PIN = 12;
const unsigned long HALBES_BIT_US = 500; // 1000 bps

void manchester_bit_senden(bool bit) {
    if (bit) {
        // Logisch 1: Übergang Low → High
        digitalWrite(SENDE_PIN, LOW);
        delayMicroseconds(HALBES_BIT_US);
        digitalWrite(SENDE_PIN, HIGH);
        delayMicroseconds(HALBES_BIT_US);
    } else {
        // Logisch 0: Übergang High → Low
        digitalWrite(SENDE_PIN, HIGH);
        delayMicroseconds(HALBES_BIT_US);
        digitalWrite(SENDE_PIN, LOW);
        delayMicroseconds(HALBES_BIT_US);
    }
}

void paket_senden(const uint8_t* daten, size_t laenge) {
    for (size_t i = 0; i < laenge; i++) {
        for (int bit = 7; bit >= 0; bit--) {
            bool aktuelles_bit = (daten[i] >> bit) & 0x01;
            manchester_bit_senden(aktuelles_bit);
        }
    }
}
```

## Phase 3
Felderprobung in einer überdachten Tiefgarage, die eine 10-Meter-V2V-Sichtverbindung simuliert. Messung der Bitfehlerrate in Abhängigkeit von der Entfernung; Umgebungslichtsättigung wurde als primärer Ausfallmodus oberhalb von ca. 30 klux identifiziert.

## Was ich anders machen würde

- **Fotodiode mit schmalem Sichtfeld und optischem Bandpassfilter**: Die von mir verwendete Weitwinkel-Fotodiode wurde bei direkter Sonneneinstrahlung gesättigt — ein K.O.-Kriterium für Außen-V2V-Szenarien. Ein Empfänger mit schmalem Sichtfeld-Kegel in Kombination mit einem Hardware-Bandpassfilter, der auf den Emissionspeak der LED abgestimmt ist, hätte die Umgebungssättigung auf analoger Ebene — noch vor dem TIA — blockiert.
- **Hardwarebasierte Manchester-Kodierung über SPI oder eine programmierbare Zustandsmaschine**: Die Soft-Codierung der Manchester-Zeitvorgaben in der Haupt-CPU-Schleife funktionierte bei 1000 bps, erzeugte aber Jitter, der bei höheren Baudraten zu Dekodierfehlern führte. Die Auslagerung der Kodierung auf dedizierte Hardware — einen SPI-Peripherie mit festem Takt oder eine benutzerdefinierte programmierbare Zustandsmaschine auf einem MCU mit PIO-Unterstützung — hätte eine deterministische Zeitgebung unabhängig von Interrupt-Latenzen ermöglicht.
- **Adaptives dynamisches Schwellenwertverfahren für das Bit-Slicing**: Ich verwendete einen festen Spannungsschwellenwert am Komparator des Bit-Slicers. Entfernungsfluktuationen und atmosphärische Streuung verschoben die Amplitude des empfangenen Signals so stark, dass der feste Schwellenwert instabil wurde. Ein adaptiver Algorithmus, der über ein gleitendes Fenster den Signalhüllkurven-Mittelwert verfolgt und den Schwellenwert dynamisch aktualisiert, hätte die Übertragungsstrecke robuster gegenüber wechselnden Betriebsbedingungen gemacht.
